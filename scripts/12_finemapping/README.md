# Fine-mapping: LOCO SuSiE-adj and SuSiE-RSS

These scripts are the fine-mapping implementations used for the BOLT-LMM and REGENIE-LOCO benchmark comparison. They include preparation, fitting, evaluation, publication comparisons, and high-PIP window summaries. No fitted objects or individual-level data are included.

## Software and inputs

Use R with **susieR 0.14.2**, data.table and ggplot2; Python with numpy, pandas, scipy and matplotlib; and PLINK and MPH for preparation. The LOCO calculations use the LD-adjustment algebra directly in Python. Configure your R library through the standard `R_LIBS_USER` environment variable if needed.

Required benchmark inputs, with the names consumed by the scripts:

- `BOLTLMM/bolt_pheno{1..10}.stats` and `BOLTLMM/boltlmm.log` (including variance-component estimates).
- `REGENIE/regenie_pheno{p}_pheno{p}.regenie` and `REGENIE/regenie_step1_pheno{p}_1.loco` predictions.
- `simu_pheno/IID.txt` (20,000 GWAS sample IDs) and `simu_pheno/pheno_combined.txt`.
- `eligible_regions.csv` and `snp.info.chr1_18.10k.csv` for evaluation only.
- Original PLINK genotype data and SNP metadata for preparation, supplied through the environment variables below.
- `chr1_18_lengths.csv` in `SIMULATION_DIR` for the LOCO evaluation.

The code retains the benchmark's sample counts, SNP counts, schemas and phenotype names as explicit checks. It is not a generic fine-mapping interface for arbitrary datasets.

## Install into a benchmark workspace

The installer preserves the original relative directory layout used by both pipelines. It creates output directories and copies code only. It refuses to overwrite different existing files; use a separate workspace when preserving an older analysis.

```bash
python3 scripts/12_finemapping/install_workflow.py /path/to/benchmark
export BENCHMARK_ROOT=/path/to/benchmark
export GENO_SOURCE=/path/to/original_panel_prefix
export REGENIE_GENO_SOURCE=/path/to/regenie_panel_prefix
export SNP_INFO_SOURCE=/path/to/snp_info.csv
export SIMULATION_DIR=/path/to/simulation_metadata
# Optional executable locations; defaults are plink and mph on PATH.
export PLINK_BIN=/path/to/plink
export MPH_BIN=/path/to/mph
```

`GENO_SOURCE` and `REGENIE_GENO_SOURCE` are PLINK prefixes (without `.bed`). The preparation audit checks their consistency with the GWAS panel. `SNP_INFO_SOURCE` is the full panel SNP metadata, not the causal-SNP list.

## Run in dependency order

Preparation creates the 20,000-animal genotype subset, checks the MPH GRM, and writes the shared `loci/manifest.tsv` using GWAS data without causal labels:

```bash
cd "$BENCHMARK_ROOT/SuSiE_adj_finemapping"
bash scripts/prepare.sh
```

Run LOCO-adjusted LD, primary SuSiE-adj fits, and evaluation in sequence. The second command must complete successfully before the third:

```bash
cd "$BENCHMARK_ROOT/SuSiE_adj_finemapping/loco"
python3 scripts/L1_grm_crossprod.py
bash scripts/run_L2_all.sh 6 12
bash scripts/run_L4_L6.sh
```

`run_L2_all.sh` takes concurrent chromosome jobs and threads per job. Its default is 6 jobs × 12 threads. These analyses allocate dense 20,000 × 20,000 matrices and require substantial memory. Adjust concurrency to the available resources. The fit runner uses 40 R workers; edit that setting if needed.

Then run ordinary-LD SuSiE-RSS and its comparison with the completed LOCO results:

```bash
cd "$BENCHMARK_ROOT/SuSiE_finemapping"
bash run_all.sh
python3 scripts/04_publication_comparison.py
python3 scripts/05_pip_maf_matched.py
python3 scripts/06_localization_precision.py
python3 scripts/07_high_pip_window_percentages.py
```

The RSS runner uses 20 R workers. `05` produces the saved high-PIP calls consumed by `06` and `07`; `07` also checks its counts against the table generated by `06`. No new GWAS or phenotype simulation is performed by this workflow.

## Implementations and settings

| Component | Code | Key settings |
| --- | --- | --- |
| Shared preparation | `SuSiE_adj_finemapping/scripts/prepare.sh`, `audit.R`, `common.R` | Genotype audit and GWAS-selected locus manifest |
| LOCO cross-products and adjusted LD | `SuSiE_adj_finemapping/loco/scripts/L1_grm_crossprod.py`, `L2_loco_ld.py`, `common.py` | Leave-chromosome-out GRM; method-specific variance ratio |
| SuSiE-adj | `SuSiE_adj_finemapping/loco/scripts/L4_susie_adj_loco.R` | Adjusted LD, effective sample size, `estimate_residual_variance=TRUE` |
| SuSiE-RSS | `SuSiE_finemapping/scripts/01_ordinary_ld.py`, `02_susie_rss.R` | Ordinary Pearson LD, `n=20000`, `estimate_residual_variance=FALSE` |
| Comparison/evaluation | `SuSiE_finemapping/scripts/03_evaluate_and_plot.py` through `07_high_pip_window_percentages.py` | Matched comparisons, MAF expectations, precision and effect/null percentages |

Both fitters use `L=10`, coverage `0.95`, minimum absolute correlation `0.5`, and `max_iter=1000`. They retain the same GWAS statistics, harmonization and locus manifest. Causal labels are used after fitting for evaluation. The comparison changes LD, sample-size input and residual-variance estimation; it is a comparison of pipelines, not an isolated LD-only intervention.

LOCO primary failures and nonconvergence are recorded. Any `sens_ERV_FALSE_*` sensitivity fits are separate from primary results. The current comparison uses the `loco/` branch of SuSiE-adj, not older whole-genome-GRM fits.

High-PIP analyses use **PIP ≥ 0.9** and count a SNP once per GWAS method, pipeline and phenotype. Pooled percentages are ratios of summed counts across phenotypes. Effect/null membership uses each SNP's own position. Known simulated causal SNPs are distinguished from high-PIP predictions.

## Outputs and validation

Per-locus outputs include `snp_pip.tsv`, `credible_sets.tsv`, fit summaries and harmonization checks. RSS comparison tables appear in `SuSiE_finemapping/results/`; publication evaluations appear in its `publication/` subdirectories; effect/null percentages appear in `results/high_pip_window_percentages/`.

The packaged code preserves the original analysis calculations. Packaging changes configure external input paths, derive internal paths from the installed layout, initialize directories, and replace the old PID-dependent wait with a requirement to run stages sequentially. Python/R/shell syntax, installation behavior, and the high-PIP summary were checked during packaging. Full genotype-based fitting was not rerun for this repository update.
